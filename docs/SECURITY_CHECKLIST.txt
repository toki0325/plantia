## SECURITY_CHECKLIST.txt
PLANTIA（ガーデニング用品ECサイト）実装時セキュリティチェックリスト

DESIGN.txt / PROJECT_GUIDE_1.txt に基づく実装と並行して、Cursor/Claude Codeが
各STEPで満たすべきセキュリティ要件をまとめたもの。特にPROJECT_GUIDE_1.txt STEP3の
優先度1（購入導線）・優先度3（会員機能）実装時に必ず参照すること。

---

## 0. このファイルの使い方
- 実装を1ページ・1機能追加するたびに、該当する項目にチェックが入る状態を目指す
- 「MVPのため対応不要」と判断した項目は、その理由をコメントとしてコード内かPRメモに残す
- 決済（KOMOJU）・会員情報まわりは特に厳格に扱う（本チェックリストの最重要項目）

---

## 1. 環境変数・シークレット管理
- [ ] KOMOJUのAPIキー・シークレットキーはすべて環境変数（.env.local）で管理し、コードにハードコードしない
- [ ] .env.local / .env* を .gitignore に含め、リポジトリにコミットしない
- [ ] .env.example を用意し、必要な変数名のみ記載（実際の値は書かない）
- [ ] クライアントサイド（ブラウザに配信されるコード）に秘密鍵・シークレットを一切露出しない（NEXT_PUBLIC_接頭辞の誤用に注意）

## 2. 決済（KOMOJU）まわり
- [ ] 決済処理・金額計算はすべてサーバーサイド（Route Handler/Server Action）で行い、クライアントから送られた金額をそのまま信用しない
- [ ] KOMOJUからのWebhook通知は署名検証を行ってから処理する
- [ ] 決済ステータスの確定はWebhook（またはサーバー側APIでの照会）を正とし、クライアントのリダイレクト結果だけで「購入完了」を確定しない
- [ ] テスト用キーと本番用キーを環境変数で明確に分離する
- [ ] 送料無料ライン（11,000円以上）や送料計算のロジックもサーバーサイドで検証し、クライアント側の表示値を信用しない

## 3. 認証・会員機能
- [ ] パスワードは平文で保存せず、ハッシュ化（bcrypt等）して保存する
- [ ] セッション/認証トークンはHTTP-only・Secure・SameSite=Lax以上のCookieで管理する
- [ ] ログインフォームにはレート制限（一定回数失敗でロック/待機）を設ける
- [ ] パスワードリセット等の機密操作はトークンに有効期限を設定する
- [ ] マイページ・注文履歴など会員専用ページは、サーバーサイドでログイン状態を検証してから表示する（クライアント側のみの判定にしない）
- [ ] MVPではダミー認証で先行実装してよいが、本番リリース前に上記項目をすべて満たす実装に置き換える

## 4. 入力値・フォーム
- [ ] お問い合わせ・レビュー投稿（表示のみのMVPでも将来投稿機能を追加する前提で）・会員登録などすべての入力フォームでサーバーサイドバリデーションを行う（クライアント側のみの検証で済ませない）
- [ ] ユーザー入力をそのままHTMLに出力しない（Reactのデフォルトエスケープに任せ、dangerouslySetInnerHTMLの使用は原則禁止）
- [ ] 検索・カテゴリ絞り込み・「育てやすさ・条件から探す」タグ絞り込み等のクエリパラメータは想定外の値が来てもエラーにならないよう検証する
- [ ] ファイルアップロード機能（レビュー画像等）：MVPでは非搭載のため対象外。将来追加時は拡張子・MIMEタイプ・ファイルサイズを制限すること

## 5. HTTPヘッダー・通信
- [ ] 本番環境は常にHTTPSで配信する（Vercel等のホスティングではデフォルト対応が多いが確認する）
- [ ] Content-Security-Policy（CSP）を設定し、想定外の外部スクリプト読み込みを防ぐ
- [ ] X-Frame-Options / X-Content-Type-Options 等の基本セキュリティヘッダーを設定する（next.config.jsのheaders()等）

## 6. 個人情報・ログ
- [ ] 注文者情報・配送先住所・電話番号などの個人情報はログに出力しない（console.logへの丸ごと出力を避ける）
- [ ] エラーメッセージはユーザー向けには一般的な文言に留め、スタックトレースや内部情報を画面に表示しない
- [ ] 個人情報保護方針（プライバシーポリシーページ）の記載内容と、実際に収集・利用しているデータ項目（氏名・住所・電話番号・メールアドレス・購入履歴等）に齟齬がないか確認する
- [ ] ニュースレター登録（メールマガジン）機能を実装する場合、配信停止（オプトアウト）導線を必ず用意する

## 7. 依存パッケージ・ビルド
- [ ] npm audit（またはyarn audit）を定期的に実行し、重大な脆弱性が出ていないか確認する
- [ ] 使用していないパッケージ・サンプルコードの消し忘れ（デモ用の管理画面や認証バイパス等）がないか確認する

## 8. MVPフェーズでの明示的な非対応事項
以下はMVPのため厳格な対応は不要だが、将来的な拡張時には要対応として明記しておく：
- 二段階認証（2FA）
- WAF（Web Application Firewall）の導入
- 高度な不正注文検知（機械学習ベースの不正検知等）
- レビュー投稿機能（画像アップロード含む本格実装）
- 庭のレイアウトシミュレーター等、外部連携を伴う大掛かりな機能
